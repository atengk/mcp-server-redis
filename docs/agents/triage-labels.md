# 分流标签规范 (Triage Labels)

工程技能遵循五大标准分流角色。本文档将这五种标准角色映射至本项目 GitHub Issues 实际使用的标签字符串。

---

## 标签映射对照表

| 技能标准标签 | 本项目实际标签 | 语义说明与工作流转要求 |
| :--- | :--- | :--- |
| `needs-triage` | `needs-triage` | **待分流**：新提交的任务或问题，需要维护者评估、确认与初筛 |
| `needs-info` | `needs-info` | **待补充**：信息不足，等待问题提出者补充重现步骤、配置细节或环境上下文 |
| `ready-for-agent` | `ready-for-agent` | **就绪可执行 (Agent)**：需求契约完整清晰，无需外部交互，可由自治 Agent 独立编码实施 |
| `ready-for-human` | `ready-for-human` | **需人工介入**：涉及重构决策、敏感操作、权限审批或边界复杂，需人类工程师推进 |
| `wontfix` | `wontfix` | **不予处理**：偏离项目范围、无法复现、重复报告或经评估已决定不作支持 |

---

## 标签使用指引

- 当工程技能指示某种分流操作（例如“应用就绪可执行标签”）时，统一使用上表映射的对应标签字符串；
- 若后续团队标签规范有所调整，仅需直接修改上表中“本项目实际标签”一列即可无缝适配。
