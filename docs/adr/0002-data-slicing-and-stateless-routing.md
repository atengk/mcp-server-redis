# ADR-0002: 数据结构安全切片策略与无状态多库路由设计

- **状态**: 已采纳 (Accepted)
- **决策日期**: 2026-10-04

---

## 背景与问题陈述

在第二轮设计推演中，针对大模型调用 Redis 服务的具体交互特征，面临以下关键工程权衡：
1. **键空间遍历体验与效率**：Redis 原生 `SCAN` 基于游标分批返回（每次可能返回 0 个或少量匹配键），大模型对多轮驱动游标翻页的处理能力较弱且频繁耗费对话 Token；
2. **大集合 OOM 风险**：针对生产环境中可能包含数万甚至数百万元素的 Hash、List、Set、ZSet 以及 Stream，若缺乏统一防线，大模型调用获取全量数据将引发内存撑爆或响应超时；
3. **多库切换的并发安全性**：传统客户端通过连接状态执行 `SELECT <db>` 命令，在高并发或异步 MCP 工具调用环境下，极易产生连接状态污染和跨会话“串库”问题。

---

## 决策内容

1. **智能聚合键扫描器 (Aggregated Key Scanner)**：
   - 工具对外隐藏 Redis 底层游标参数，直接暴露 `redis_scan_keys(pattern: str = "*", limit: int = 50, type: str = None)`；
   - 底层代码由服务内部自动循环调度 `SCAN` 游标，累积收集匹配键直至达到 `limit`（硬上限 200 条）或全库迭代完毕，单次调用即可返回完整的结果数组。

2. **核心 5 基础结构 + Stream 消息流支持与全量切片防护**：
   - 支持 **String、Hash、List、Set、ZSet** 及 **Stream**；
   - 所有集合读取工具强制限制单次返回数量：
     - Hash 字段读取默认单次最多 50 个；
     - List 切片跨度 `stop - start` 强制不超过 100；
     - Set 采样默认 50，硬上限 200；
     - ZSet 范围查询默认 50，硬上限 200；
     - Stream 消息逆序采样默认获取最新 20 条，硬上限 100 条。

3. **双层无状态路由 (Stateless Routing)**：
   - 所有 MCP 工具统一支持可选参数 `connection: str = None` 与 `db: int = None`；
   - 连接注册中心在派发底层连接时，动态使用指定逻辑库连接池或参数化连接上下文执行，**严禁在共享连接上执行有状态的 `SELECT <db>` 指令**。

4. **运维诊断聚焦核心单机/主从套件**：
   - 优先建设高内聚的实例级指标与诊断工具：`redis_ping`、`redis_info`、`redis_dbsize`、`redis_key_inspect` (内存/编码/TTL)、`redis_slowlog` 与 `redis_client_list`；
   - 暂不扩展复杂的多分片 Redis Cluster 拓扑槽位管理。

---

## 影响与权衡

- **积极收益**：
  - 大模型交互体验极大简化，单次对话即可获取模式匹配的 Key 列表；
  - 彻底规避大集合引发的客户端/服务端 OOM 风险；
  - 无状态路由彻底根绝异步并发环境下的跨库污染隐患。
- **潜在代价与权衡**：
  - 内部聚合扫描在超大键空间且匹配率极低的场景下，可能单次调用耗时稍长（需内置最大遍历轮次保底保护，防死循环）。
