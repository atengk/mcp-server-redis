# ADR-0001: 核心技术栈与安全守卫架构选型

- **状态**: 已采纳 (Accepted)
- **决策日期**: 2026-10-04

---

## 背景与问题陈述

大语言模型（LLM）具备自主调用外部工具（Tool Calling）的能力。在引入 Redis 作为外部上下文存储与运维分析对象时，面临以下核心挑战：
1. **指令破坏性与全库阻塞风险**：Redis 原生命令如 `FLUSHALL`、`KEYS *` 等在生产环境下会引发灾难性数据丢失或主线程阻塞崩溃；
2. **连接灵活性与使用门槛**：既需支持开发者单机调试（免复杂配置，开箱即用），又需支持企业多环境（测试/预发/生产只读）多实例路由；
3. **数据变更与安全管控**：大模型偶发的语义漂移或幻觉可能触发非预期的键值覆盖或数据删除。

---

## 决策内容

经过设计推演，确立以下四项核心架构决议：

1. **技术栈与协议底座**：
   - 采用 **Python (>=3.10)** 作为核心语言；
   - 基于 **FastMCP (Official MCP SDK)** 构建协议接入层；
   - 底层采用高性能 **`redis-py`** 异步连接池支撑高并发与流式通信。

2. **双轨功能定位**：
   - 兼顾“**数据探查与读写**”与“**运维性能与诊断**”两大业务轨；
   - 通过清晰的命名空间（如 `redis_data_*` 与 `redis_admin_*`）实现模块化解耦与职责隔离。

3. **自适应双模连接管理**：
   - **单实例开箱即用**：支持直接通过环境变量 `REDIS_URL` 或 CLI 参数 `--url` 直连单个 Redis；
   - **多连接配置中心**：支持通过 `--config <path>` 加载 YAML/JSON 配置文件，注册多实例连接档案（Connection Profile），并在工具调用时按需路由。

4. **安全守卫与权限模型**：
   - **默认强只读**：默认启动为只读模式，所有写入、删除与过期变更操作一律拦截并返回权限阻断错误；
   - **显式写授权**：仅当启动命令显式传入 `--allow-write` 时，方可放行常规写操作；
   - **物理阻断破坏性指令**：不论是否启用写授权，底层永久物理硬编码拦截 `FLUSHALL`、`FLUSHDB`、`KEYS *`、`SHUTDOWN`、`CONFIG` 等高危命令。

---

## 影响与权衡

- **积极收益**：
  - 彻底规避大模型因幻觉执行删库或全实例阻塞的重大事故；
  - 兼顾单机极速试用（`uvx` 直连）与复杂多环境配置需求；
  - Python 与 FastMCP 拥有优秀的生态兼容性与快速迭代能力。
- **潜在代价与权衡**：
  - 不支持通过 MCP 工具动态修改 Redis 服务端配置（如 `CONFIG SET`），此类操作须通过传统运维运维通道进行；
  - 写操作需要启动参数显式授权，对需要即时变更的场景增加了一次参数启动约束。
