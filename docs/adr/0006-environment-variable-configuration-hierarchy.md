# ADR-0006: 环境变量配置分级决议、离散参数组装与安全加载策略

- **状态**: 已采纳 (Accepted)
- **决策日期**: 2026-10-04

---

## 背景与问题陈述

在大语言模型客户端（如 Claude Desktop、Cursor、Cline、Windsurf、Cherry Studio 等）及云原生容器（Docker、Kubernetes）生态中，通过环境变量（Environment Variables）注入配置是跨平台最通用、最安全的做法。在此场景下面临以下架构设计问题：
1. **传参形式多样性**：部分系统仅支持提供单一连接串（`MCP_REDIS_URL`），而大部分云原生配置与 PaaS 平台倾向分发离散字段（`MCP_REDIS_HOST`、`MCP_REDIS_PORT`、`MCP_REDIS_PASSWORD`、`MCP_REDIS_DB`）；
2. **命名空间与环境污染**：原生裸 `REDIS_*` 变量极易与宿主机上其他 Redis 客户端工具或服务产生名称冲突，必须采用专属的 `MCP_REDIS_` 前缀；
3. **密码特殊字符冲突**：生产密码常包含 `@`、`:`、`/` 等特殊符号（例如 `Admin@123`），若由用户手工拼装整串 URL，极易发生语法截断或 netloc 解析分裂崩溃；
4. **权限与配置无法通过环境配置**：此前写权限 `--allow-write` 与多连接配置 `--config` 仅支持 CLI 参数，导致在仅支持 `env` 配置的客户端中无法启用写权限或挂载多实例；
5. **层级覆盖与环境安全**：系统级、用户级、客户端级环境变量以及本地 `.env` 文件可能同时存在，需确立严密的优先级裁决顺序，防止本地文件越权覆盖操作系统级环境变量。

---

## 决策内容

经过设计推演，确立以下架构决议：

1. **建立规范严谨的 MCP 专属环境变量覆盖集 (B-A-B 规范)**：
   - **整串直连**：`MCP_REDIS_URL`；
   - **离散连接字段**：`MCP_REDIS_HOST`（默认 `localhost`）、`MCP_REDIS_PORT`（默认 `6379`）、`MCP_REDIS_PASSWORD`、`MCP_REDIS_DB`（默认 `0`）、`MCP_REDIS_USERNAME`；
   - **多实例配置**：`MCP_REDIS_CONFIG`；
   - **写权限双通道决议**：正向授权 `MCP_REDIS_ALLOW_WRITE`（支持 `"1"`, `"true"`, `"yes"`, `"on"`）与反向只读解除 `MCP_REDIS_READ_ONLY`（支持 `"0"`, `"false"`, `"no"`, `"off"`）；
   - **废除泛滥别名**：移除 `REDIS_AUTH`、`REDIS_CONFIG_PATH` 等别名及裸前缀，保持环境变量集合的纯粹与一致。

2. **凭据特殊字符自动 URL 编码防御**：
   - 由离散参数组装连接串时，底层自动对密码与用户名执行 `urllib.parse.quote(..., safe="")`；
   - 用户只需提供明文密码，彻底免除手动 `%40` 编码的心智负担。

3. **严格的工业级配置优先级裁决层级**：
   $$\text{CLI 显式参数} > \text{系统/用户/客户端环境变量 (整串/路径)} > \text{离散参数自动组装} > \text{.env 本地文件} > \text{默认保底值}$$

4. **内置无依赖的轻量级 `.env` 探测器**：
   - 服务启动时自动检测当前工作目录下的 `.env` 文件并解析注入；
   - **最高安全守则**：仅补充注入当前 `os.environ` 中不存在的变量，已存在的系统级、用户级与进程级环境变量拥有绝对保留权。

---

## 影响与权衡

- **积极收益**：
  - 各大 MCP 客户端的 `env` 配置体验大幅简化，支持免 CLI 参数全环境变量启动；
  - 彻底终结特殊字符密码引发的连接解析崩溃隐患；
  - 本地开发与容器部署具备自解释的配置层级，符合 12-Factor App 云原生规范。
- **潜在代价与权衡**：
  - 增加了配置决议与参数组装逻辑，已通过 `core/env.py` 伴生模块独立抽离解耦并由 `tests/test_env.py` 完整覆盖。
